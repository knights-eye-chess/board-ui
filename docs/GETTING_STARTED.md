# Getting started

Board UI handles drawing and interaction. Your app supplies the position, decides
which moves are legal and updates the game after a move. You can start with a
display-only board, then add interaction when you have a chess model.

## Install

The package is not yet published on npm. Download the
[dev.26 archive](https://github.com/knights-eye-chess/board-ui/raw/refs/heads/dev/artifacts/knights-eye-chess-board-ui-0.1.0-dev.26.tgz)
and run this in your app:

```sh
npm install ./knights-eye-chess-board-ui-0.1.0-dev.26.tgz
```

Use imports through your app's existing bundler. The package includes JavaScript,
TypeScript declarations and artwork, with no runtime dependencies.

## Make the pieces available to the browser

Copy the included pieces into a directory your app serves:

```sh
mkdir -p public/pieces
cp node_modules/@knights-eye-chess/board-ui/assets/pieces/*.png public/pieces/
```

If `public/` is your web root, `/pieces/wp.png` should show a white pawn.
Installing a package does not automatically serve its images. If your site lives
under a subpath, use that prefix in `pieceUrl`, or use URLs generated by your
bundler. Piece filenames use `w`/`b` for color and `p`, `r`, `n`, `b`, `q`, `k`
for the piece: `wn.png` is a white knight, `bk.png` a black king.

You can also supply your own images. See [Appearance](APPEARANCE.md).

## Show a position

Add `<div id="board" style="width: min(100%, 480px)"></div>` to your page and
use the [README's first-board example](../README.md#get-started).

Positions map square names to pieces. Uppercase letters are White; lowercase
letters are Black. Empty squares are omitted. For example,
`{ e1: 'K', e8: 'k', e2: 'P' }` places two kings and a white pawn.

The board fills its container and stays square. Set the container's width to
control its size. Each board has independent state and appearance.

## Let people move a piece

This complete example lets a player move the pawn from e2 to e3 or e4, once.
Those two legal moves are supplied explicitly; a full chess app should obtain
them from its chess model. Add the same `#board` container and served images as above.

```js
import { mountControlledBoard } from '@knights-eye-chess/board-ui';

let state = {
  position: { e1: 'K', e8: 'k', e2: 'P' },
  orientation: 'white',
  positionKey: 'start',
  selectedSquare: null,
  permissions: { select: true, move: true, draggable: true },
  legalMoves: ['e2e3', 'e2e4']
};

const board = mountControlledBoard(document.querySelector('#board'), {
  state,
  pieceUrl: piece => `/pieces/${piece === piece.toUpperCase() ? 'w' : 'b'}${piece.toLowerCase()}.png`,
  onSelect(square) {
    state = { ...state, selectedSquare: square };
    board.update(state);
  },
  onMove(intent) {
    if (!state.legalMoves.includes(intent.uci)) return;
    const position = { ...state.position };
    position[intent.to] = position[intent.from];
    delete position[intent.from];
    state = {
      ...state, position,
      positionKey: intent.uci,
      acceptedIntentId: intent.intentId,
      selectedSquare: null,
      legalMoves: [],
      lastMove: [intent.from, intent.to]
    };
    board.update(state);
  }
});
```

Tap/click the pawn and a destination, or drag it. The callback updates the
position. Echoing `intentId` as `acceptedIntentId` tells the board it accepted
that exact move, so an accepted drag does not animate a second time.

For real games, use your model to validate and apply moves, handle captures,
castling and promotion, and produce the next legal-move list. The
[chessops demo host](https://github.com/knights-eye-chess/board-ui/blob/dev/examples/demos/src/model.mjs) is a working example.

Change `positionKey` whenever navigating to another occurrence in a game, even
when two occurrences have the same arrangement of pieces. Call `board.dispose()`
when removing the board from your app. See the [API reference](API.md) for details.

## Use a browser without a bundler

You can serve the package's `dist/` files directly. Copy that directory to your
public directory as `board-ui/`, keep the JavaScript files together, and add this
before your module script:

```html
<script type="importmap">
{
  "imports": {
    "@knights-eye-chess/board-ui": "/board-ui/controlled-board.js",
    "@knights-eye-chess/board-ui/appearance": "/board-ui/appearance.js",
    "@knights-eye-chess/board-ui/move-strip": "/board-ui/move-strip.js",
    "@knights-eye-chess/board-ui/viewer": "/board-ui/viewer.js"
  }
}
</script>
```

Then place your JavaScript in `<script type="module">` or a module file. Serve
the page over HTTP; opening it as a local file will not provide the same module
loading behavior. Adjust these paths if your site uses a subpath.
